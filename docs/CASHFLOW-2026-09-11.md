# 卡費金流與滾動配置修正

狀態：候選版，併入 PR #2；尚未合併或部署正式站。只維護 `zackc777/millionproject1`。沒有修改正式 Supabase 資料、schema、Edge Functions 或排程。

## 問題與修正

原 `moneyEngine` 只讀 `finance_entries`，在刷卡時就減少現金，沒有讀取 `credit_card_payments`。付款月份因而看不到卡費現金支出，配置公式則只看收入與整月預算，沒有扣掉已執行的存投與付款。兩個配置區塊加上遠端 payday 建議重複使用固定比例。

目前以 `src/finance-model.js` 統一計算，保留刷卡日消費認列，新增付款日現金扣款。月度頁、總覽與信用卡頁共用同一模型。月度明細包含付款，連到同一套付款 CRUD。繳款表單可以修改卡片、期別、日期、金額與備註；修改、移月或刪除後重讀資料並留在原模組。沒有在載入頁面時自動補寫交易。

| 指標 | 計算 |
|---|---|
| 消費支出 | 當月一般消費，包含刷卡；不含卡費付款 |
| 現金支出／扣款 | 當月現金消費 + 付款日期屬於當月的卡費 |
| 當月資金餘額 | 當月收入 − 現金扣款 − 已存款 − 實際投資 |
| 累計現金 | 截至所選日期的收入 − 現金扣款 − 存款轉出 − 實際投資 |
| 卡債 | 逐卡、逐期的消費減同一期付款，餘額不跨卡／跨期抵銷 |
| 淨資產 | 現金 + 存款 + 投資資產 − 卡債 |

包含所有未繳期別，不只上一期。繳款歷史不再截斷為八筆。新付款可記舊帳單與實際扣款日，未來日期不能當作已付款。若只有付款、沒有對應消費，現金仍扣除，顯示舊帳單／溢繳／漏記提示，不虛構本月消費或新增一筆可用資產。舊字串只有唯一匹配才歸卡；無法匹配時暫停追加配置建議。

帳務查詢明確限制使用者，分頁取齊超過 1,000 筆的資料；讀取失敗時不以零筆資料替代。以台北日期界定本月與已發生金流，排除固定模板及尚未到日的交易。

## 滾動建議

原「發薪日配置」改為「現在還能怎麼分」，另一區改成「花費變化與下一步」。移除 features 中額外插入的重複 payday 卡片與未確認實際轉帳的一鍵配置。一般存款記帳與快速操作仍保留。

1. 固定生活責任保留預算扣除已付部分。
2. 可分類的變動消費，參考預算、最近三個有消費紀錄月份範圍內的中位數，以及本月滿七天後的消費速度，取較高值。沒有紀錄的月份不當作零消費樣本。
3. 舊帳單彙總與其他未分類消費不自動推估成重複生活費；仍計入實際消費與現金／卡債。
4. 從當月資金餘額與累計現金的較低值，扣除卡債與剩餘生活費，得到剩餘可配置上限。
5. 保留約一週變動生活費緩衝，優先補足使用者設定的預備金目標，再列出投資可用上限。這是預算規則，不代表必須全數投資。
6. 顯示類別變化、上月同期比較、整月預估與剩餘每日預算。資料不足會說明；過去／未來月份不產生今天的追加配置。

預算更新成功後，兩個區塊一起重算；雲端寫入失敗保留舊設定且不顯示同步成功。既有固定／彈性選項不因改金額而消失。數字依使用者已記錄資料估計，不能把漏記推測為零支出。

## 手機與既有模組

付款歷史改為逐筆卡片，保留卡片、金額、付款日、結帳日、備註與編輯／刪除。月度明細加上小螢幕逐列呈現，表單 grid 子項允許縮小。總覽、信用卡與月度頁顯示一致的現金／消費摘要。無薪資月份仍可查看或維護既有扣款。

shell、icons、investment-core、investment-guard 的來源 hash 仍與正式 baseline 完全相同。新增兩個財務共用模組後，共 13 個固定同源 JS；既有 9 個 runtime 的相對載入順序不變。本次沒有新增 View Transition 或 render wrapper。

## 驗證與限制

- Node.js 24：36 項測試與 build 通過。涵蓋跨月／同月刷卡付款、部分繳款、多期欠款、不同卡片隔離、舊帳單、日期邊界、付款全欄位 CRUD、取消／未來扣款阻擋、移月重算、超支推估、歷史不足、負現金、模板排除、分頁取齊、月度與總覽整合、預算同步失敗，以及既有信用卡／投資分流回歸。
- 本地 HTTP 驗證：首頁、release.json、13 個 JS endpoint 與本地 manifest 的內容 hash 相符。這不是 Vercel preview 或正式站驗收。
- 正式資料僅做唯讀核對；測試資料均為合成資料，沒有將私人記帳資料提交至 repository。
- 桌機候選版瀏覽器測試未完成：Cloud Browser 對本地網址回覆 `ERR_BLOCKED_BY_CLIENT`。手機實際 viewport 與登入後端到端 CRUD 也未通過，不以 VM／HTML 檢查冒充瀏覽器驗收。
- Vercel 團隊 API 上次回覆 403，既有 PR preview 要求 Vercel 登入；沒有繞過保護或要求使用者重新設定。必須在可用驗收環境核對實際候選部署，才能合併發布。

新快照於 notes 保存卡債、現金扣款與投資估值，避免從淨資產減現金倒推投資時多扣卡債。卡費修改不重寫過去快照中的市場估值；歷史資產快照保留當時數值，與後補金流的區別已標示。既有其他 CRUD 的歷史估值處理、期初資產、改結帳日的歷史歸屬、退款／溢繳抵下期、資料庫並行寫入及冪等仍需要後續獨立處理。
